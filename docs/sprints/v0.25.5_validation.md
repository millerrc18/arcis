## Known upstream limitation — #552

1,424 rows ended with `sections_json = '{}'`. Diagnosed in Pass 2: `_lookup_primary_document` resolves some filings to iXBRL or SGML submission-header documents instead of the narrative HTML. The parser correctly returns `{}` on these — no `Item N. …` text to match.

Filed as **#552**: "_lookup_primary_document pulls iXBRL/SGML instead of narrative HTML for ~34% of edgar_filings". Fix lives in the fetcher, not the parser. Out of scope for v0.25.5.

The mark-attempted semantic (Option 2) is what makes this queryable:

```sql
-- Rows affected by the #552 fetcher issue:
SELECT COUNT(*) FROM edgar_filings WHERE sections_json = '{}';
-- → 1,424
```

After #552 lands, clearing `full_text` for these rows and re-running `scripts/backfill_edgar_fulltext.py` + `scripts/backfill_sections_json.py` will re-parse them cleanly.
