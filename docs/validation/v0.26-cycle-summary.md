## What this proves

**Framework-level:**
- Walk-forward v1 parses real EDGAR data, produces trades, and emits 3-state outcome with R7/R8 fields correctly populated — demonstrated twice now on two distinct specs
- INCONCLUSIVE/coverage_inconclusive correctly fires when trade density is below the `min_trades_per_window = 10` gate; aggregation is consistent across runs
- Heavy-tail bootstrap SE override fires when small-N dispersion warrants it (v0.25.3) and correctly does NOT fire when windows have single-digit N that degenerate to `MDE=inf` earlier in the state machine (v0.26.2-scoped)

**Schema-level (new in v0.26.2-scoped):**
- `universe.sector_filter` reduces the candidate ticker set before the SQL `WHERE IN (...)` query — verified by 17 non-Defensive trades being removed
- `entry.event_exclusion.categories` checks `is_known_event(entry_iso, category)` per entry — verified by test suite; no trades removed in this run (no baseline entries fell on tariff dates, so the filter had nothing to remove)
- R8 firewall correctly accepts `source_type = forensic_audit_ruleset` and correctly propagates to `walkforward_results.derived_from_source_type`

## What this does NOT prove

- **Nothing about the post-audit ruleset's trading edge.** With 3 trades, no statistical inference is possible. The forensic audit's refinement claims are untested here.
- **Nothing about the underlying strategy (cosine-similarity on 10-K/10-Q).** Both runs were underpowered at 2019-2024 coverage.
- **Nothing about the morning-only filter (#540).** That refinement is deferred pending intraday OHLCV data layer.
