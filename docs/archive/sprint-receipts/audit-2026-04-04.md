## Critical Findings

### [COMPLIANCE] DDL in scripts/ Outside Schema Registry
- **Severity**: high
- **Files**:
  - `scripts/fetch_earnings_calendar.py:33` — raw `CREATE TABLE IF NOT EXISTS earnings_calendar (...)` with a completely different schema than the registry definition
  - `scripts/recover_from_postgres.py:128` — dynamic `CREATE TABLE IF NOT EXISTS {table}` with all-TEXT columns
  - `scripts/migrate_production_db.py:39–101` — `ALTER TABLE` and `CREATE TABLE IF NOT EXISTS` blocks
- **Evidence**: CLAUDE.md mandates "NEVER write CREATE TABLE in any file except src/schema/registry.py." The CI guardrail `test_no_create_table_in_source` only scans `src/`, not `scripts/`. These three scripts define or mutate tables outside the registry.
- **Impact**: Schema drift risk — if these scripts run, they can create tables with wrong column types (all TEXT in recover_from_postgres) or add columns that conflict with the registry definition.
- **Recommendation**: Remove DDL from all three scripts. `fetch_earnings_calendar.py` should call `initialize_database()` to ensure tables exist. `recover_from_postgres.py` should restore data into tables created by the registry. `migrate_production_db.py` should be superseded by `validate-schema --fix`.

### [SECURITY] Cloud API CORS Configured as Wildcard
- **Severity**: high
- **File**: `src/api/cloud_app.py:57`
- **Evidence**: `allow_origins=["*"]` with `allow_credentials=True` on the cloud-deployed trading API. This allows any origin to make credentialed cross-origin requests to the production trading endpoints.
- **Impact**: While bearer token auth is required on most routes, CORS wildcard + credentials=True is an invalid combination per the CORS spec (browsers block it) and signals misconfiguration. If `API_SECRET` is ever unset (the code explicitly degrades to "authentication disabled"), any web page can invoke halt-trading or submit commands.
- **Recommendation**: Restrict `allow_origins` to the actual frontend domain (e.g., `["https://halcyonlab.app"]`). The local API (`src/api/app.py`) correctly restricts to localhost.

### [TEST COVERAGE] Bracket Safety Tests Fail Due to Unmocked Alpaca Import
- **Severity**: high
- **Files**:
  - `tests/test_bracket_safety.py:32,50` — `TestGTCOrderFormat` tests fail
  - `tests/test_bracket_orders.py:29,66,131` — multiple `TestBracketOrderConstruction` tests fail
  - `tests/test_live_trading.py:682` — `TestLiveAdapter::test_live_trading_client_uses_paper_false` fails
- **Evidence**: `src/shadow_trading/alpaca_adapter.py:232` has `from alpaca.trading.requests import ...` as a deferred import inside the function body. The tests mock `_get_trading_client` but the deferred `from alpaca.trading.requests import ...` still executes, raising `ModuleNotFoundError: No module named 'alpaca'`. CLAUDE.md requires all external APIs to be mocked. These tests do not satisfy that requirement.
- **Impact**: Bracket order safety tests (GTC enforcement, stop-loss/take-profit construction) cannot run in CI without the alpaca SDK installed. This is a critical testing gap for the trading execution path.
- **Recommendation**: Either (a) add `alpaca-trade-api` to `requirements.txt` so it is always available, or (b) restructure the deferred imports in `alpaca_adapter.py` so they can be patched at the module path (e.g., `patch("src.shadow_trading.alpaca_adapter.MarketOrderRequest")`), or (c) add a conditional `pytest.importorskip("alpaca")` to skip gracefully rather than fail.

## Warnings

### [ARCHITECTURE] God File: watch.py (3,067 lines)
- **Severity**: medium
- **File**: `src/scheduler/watch.py`
- **Evidence**: 3,067 lines, 30+ methods on `WatchLoop` class. The file handles scheduling, heartbeat, notifications, PID locking, database backup, bracket health, reconciliation, and daily audit — all in one class.
- **Recommendation**: Extract sub-responsibilities into helper classes or modules (e.g., `WatchNotifier`, `WatchDatabase`, `WatchScheduler`). The grandfathered size is acknowledged by `test_repo_structure.py` but it continues to grow.

### [ARCHITECTURE] Layer Violation: telegram.py Imports council.engine
- **Severity**: low
- **File**: `src/notifications/telegram.py:1147`
- **Evidence**: `from src.council.engine import CouncilEngine` — Telegram is infrastructure (Layer 1); `council` is a service (Layer 3). MASTER.md states "Imports only go DOWN. Never import from a higher layer."
- **Recommendation**: Invert the dependency — have the council or a service layer call telegram, rather than telegram importing council directly.

### [CODE QUALITY] 131 Bare `except Exception:` Handlers
- **Severity**: medium
- **Evidence**: `grep -rn 'except Exception:' src/` returns 131 matches. Many in critical paths: `src/shadow_trading/executor.py` (3), `src/shadow_trading/reconcile.py` (2), `src/shadow_trading/bracket_monitor.py` (2), `src/shadow_trading/alpaca_adapter.py` (1). Several silently swallow exceptions with no logging.
- **Notable**: `executor.py:735` — a bare `except Exception: pass` inside the exit loop means a Telegram send failure suppresses the retry notification silently. This is acceptable, but the pattern needs review to ensure no critical failures are hidden.
- **Recommendation**: Replace `except Exception:` with typed exceptions where possible. Ensure all bare exception handlers at minimum log at WARNING level with the exception text.

### [CODE QUALITY] Grandfathered Oversized Files (11 files)
- **Severity**: low
- **Evidence**: `test_repo_structure.py` emits GRANDFATHERED warnings for: `watch.py` (3,067L), `executor.py` (1,404L), `registry.py` (1,386L), `commands.py` (1,097L), `system_validator.py` (941L), `trainer.py` (794L), `cto_report.py` (754L), `render_sync.py` (690L), `analytics.py` (593L), `routes/system.py` (577L), `alpaca_adapter.py` (548L). Also 60+ grandfathered functions >60 lines.
- **Recommendation**: Stop adding to these files. Any new feature in these modules should prompt a refactor. Prioritize `watch.py` and `executor.py` as highest risk.

### [DOCUMENTATION] CLAUDE.md Table Count Stale (46 vs Actual 49)
- **Severity**: low
- **File**: `CLAUDE.md` (header section)
- **Evidence**: CLAUDE.md states "all 46 tables are defined in `src/schema/registry.py`." The actual count is 49 (`grep -c 'TableDef(' src/schema/registry.py` = 49). MASTER.md correctly states 49. Schema validation also confirms 49.
- **Recommendation**: Update CLAUDE.md to read "all 49 tables."

### [SCHEMA] fetch_earnings_calendar.py Defines Divergent Schema
- **Severity**: medium
- **File**: `scripts/fetch_earnings_calendar.py:33–45`
- **Evidence**: Defines `earnings_calendar` table with columns `(id, ticker, earnings_date, earnings_time, confirmed, collected_at)` plus three indexes. The registry definition of `earnings_calendar` may have additional columns. If this script runs before `validate-schema --fix`, it creates a schema that conflicts with the registry.
- **Recommendation**: Remove the `_INIT_SQL` block from this script entirely; call `initialize_database()` if table existence is required.

### [TEST COVERAGE] test_traffic_light.py::test_persistence_filter Fails in Isolation
- **Severity**: medium
- **File**: `tests/test_traffic_light.py:85`
- **Evidence**: Test creates a tmp SQLite DB but `compute_traffic_light()` expects `traffic_light_state` and `macro_snapshots` tables to already exist. The test does not call `initialize_database(tmp_path_db)` first. The function's `_ensure_state_table` catches the `no such table` error as a warning and silently continues — so persistence is never applied and the assertion `assert r["persistence_applied"] is True` fails.
- **Recommendation**: Add `initialize_database(db)` at the start of `test_persistence_filter` to create the required tables in the temp DB.

### [TRADING SAFETY] LLM Conviction Parsing Returns None for 143/145 Packets (Known Bug)
- **Severity**: medium
- **File**: `src/llm/packet_writer.py:361–363`
- **Evidence**: MASTER.md issue #183 documents that 143/145 conviction parses return `None`, causing all trades to use the hardcoded fallback of `conviction = 5`. The code at line 361–363 confirms this fallback: `if conviction is None: conviction = 5`. This means all risk sizing decisions that depend on conviction score are using a static default.
- **Impact**: The conviction signal, which is supposed to gate live trading (executor.py:888–890 skips live trade if conviction is None), is effectively bypassed for paper trades by defaulting to 5.
- **Recommendation**: Prioritize fixing the XML parsing regex in `_parse_llm_response`. Add a metric to track conviction parse success rate. Consider halting paper trades too if conviction is consistently None.

## Positive Findings

1. **Schema registry is solid**: 49 tables all defined in `src/schema/registry.py`. `validate-schema` passes cleanly: "Schema OK — no issues found." DDL is absent from all `src/` Python files (only violations are in `scripts/`).

2. **No hardcoded credentials in src/**: `grep` for `password =`, `secret =`, `api_key =` with literal string values in `src/` returns zero results. All secrets are read from environment variables or config files.

3. **Risk governor is well-implemented**: 8 checks, configurable thresholds, file-based kill switch that persists across restarts, drawdown computation with conservative fallback, kill switch callable from API and dashboard.

4. **Cloud API auth is properly gated**: All non-health cloud endpoints use `dependencies=[Depends(verify_auth)]`. Auth supports both hashed and raw tokens, and disables gracefully only with a loud warning log.

5. **No SQL injection from user input in logs/notes routes**: Both `src/api/routes/logs.py` and `src/api/routes/notes.py` build dynamic WHERE clauses from whitelisted column names only (never direct user string interpolation into SQL column names). Parameterized queries are used for all values.

6. **MASTER.md is comprehensive and current**: 300+ lines, covers system state, schema, architecture, known issues, sprint history, and blockers. Updated to current sprint.

7. **Test guardrails are enforced**: `test_repo_structure.py` enforces file size limits, function length limits, no DDL in `src/`, and no network calls in tests. `test_env_secrets.py` confirms secrets stay out of committed files.

8. **Bracket order safety infrastructure**: `bracket_monitor.py`, `alpaca_adapter.py`, and the executor all implement GTC bracket orders with stop-loss and take-profit. The reconciliation system monitors bracket leg fills every 15 minutes.
