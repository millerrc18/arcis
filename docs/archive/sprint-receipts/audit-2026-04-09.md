## Critical Findings

### [SECURITY] Local API endpoints have no authentication

- **Severity**: critical
- **File**: `src/api/routes/system.py:118–131`
- **Evidence**: `/halt-trading` (POST) and `/resume-trading` (POST) are registered with no
  `Depends(verify_auth)` dependency. Any process on the host that can reach the local
  FastAPI port can halt or resume live trading without a token or password. The cloud
  app counterparts at `src/api/cloud_routes/core.py:378` correctly require `verify_auth`.
  Additional unauthenticated sensitive endpoints: `/config` (exposes YAML config),
  `/cto-report`, `/costs`, `/audit/latest`, `/audit/history`.
- **Recommendation**: Add `dependencies=[Depends(verify_auth)]` to all sensitive local routes,
  or at minimum to `/halt-trading`, `/resume-trading`, and `/config`. If the local API is
  intended to be trusted (localhost-only), document that assumption explicitly and add at
  least an API-key header check consistent with the cloud layer.

### [COMPLIANCE] `src/schema/registry.py` exceeds 400-line limit — CI guardrail failing

- **Severity**: critical
- **File**: `src/schema/registry.py` (1275 lines), `src/schema/postgres.py`
- **Evidence**: `test_repo_structure.py::test_no_file_over_400_lines` **FAILS** in CI with:
  ```
  NEW VIOLATION: src/schema/registry.py is 1275 lines (max 400)
  ```
  `test_all_modules_have_standard_docstring` **FAILS** because `src/schema/postgres.py`
  is missing the required 5-field docstring header (Called by, Calls, Owns tables,
  Config keys, Tests).
  `test_every_new_table_in_render_migrate` **FAILS** with spurious match on `postgres.py`
  line 19 docstring containing the word `sql` being parsed as a table name.
  Three `test_repo_structure` tests are failing in CI on every run.
- **Recommendation**:
  1. Add `src/schema/registry.py` to `config/known_violations.json` `oversized_files`
     (it is the single-source-of-truth by design and cannot be split arbitrarily).
  2. Add standard docstring header to `src/schema/postgres.py`.
  3. Fix the `test_every_new_table_in_render_migrate` regex to only match
     actual `CREATE TABLE IF NOT EXISTS` DDL lines, not docstring text.

### [COMPLIANCE] Test fixtures contain `CREATE TABLE` DDL (20+ test files)

- **Severity**: medium
- **File**: `tests/test_council.py:66`, `tests/test_digest_builder.py`, and 18 others
- **Evidence**: `grep -rn 'CREATE TABLE' tests/` returns 20+ files. CLAUDE.md's schema
  governance rule states DDL must live only in `src/schema/registry.py`. While the
  `test_no_create_table_in_source` guardrail only scans `src/`, the pattern of
  hand-rolling DDL in tests creates schema drift (e.g., `test_council.py` fixture omits
  the `updated_at NOT NULL` column added to `shadow_trades`, causing 6 test errors).
- **Recommendation**: Replace inline DDL in test fixtures with a shared `conftest.py`
  helper that calls `src.schema.sqlite.create_all_tables(tmp_db_path)`.

### [SECURITY] `source` parameter in `/api/logs/recent` not validated

- **Severity**: low
- **File**: `src/api/cloud_routes/core.py:268–269`
- **Evidence**: The `source: str` query parameter is passed directly into a parameterized
  `WHERE source = %s` clause. This is safe against injection (value is parameterized),
  but there is no validation of allowed values, allowing arbitrary string filtering
  against the `log_entries.source` column from any authenticated caller.
- **Recommendation**: Add an optional allowlist for `source` values, or accept the current
  behaviour as an intentional flexible filter (document it).
