## Critical Findings

### [SECURITY] Local API bound to 0.0.0.0 with no authentication on sensitive endpoints

- **Severity**: critical
- **File**: `src/cli/commands.py:1289`, `src/api/routes/system.py:158–181`
- **Evidence**:
  ```python
  # commands.py:1289
  uvicorn.run("src.api.app:app", host="0.0.0.0", port=port, reload=False)
  ```
  The local API server binds to all interfaces (not `127.0.0.1`). The routes
  `/api/halt-trading` (POST) and `/api/resume-trading` (POST) carry no
  `Depends(verify_auth)` dependency and have no other access control. Any host on
  the same network can halt or resume all trading without a credential. Additional
  unauthenticated sensitive endpoints: `/api/config` (exposes full YAML config),
  `/api/cto-report`, `/api/costs`, `/api/audit/latest`, `/api/audit/history`,
  `/api/system/validation`. This finding was also flagged in the 2026-04-09 audit
  and remains unresolved.
- **Recommendation**: Either (a) change `host="0.0.0.0"` to `host="127.0.0.1"` so the
  local API is loopback-only, **or** (b) add `dependencies=[Depends(verify_auth)]` to
  all sensitive local routes consistent with the cloud layer. Option (a) is the
  lower-risk quick fix; option (b) is needed if remote access is ever required.

### [SECURITY] Cloud API silently disables authentication when `API_SECRET` is empty

- **Severity**: critical
- **File**: `src/api/cloud_app.py:116–121`
- **Evidence**:
  ```python
  if not API_SECRET:
      logger.warning(
          "[AUTH] API_SECRET is empty — authentication disabled. "
          "Set API_SECRET env var to enable auth."
      )
      return   # ← accepts all requests
  ```
  When the `API_SECRET` environment variable is missing or blank, every cloud
  endpoint that depends on `verify_auth` becomes publicly accessible — including
  `/api/commands/submit` (triggers scans/training), `/api/settings` (POST, mutates
  config), `/api/actions/scan`, `/api/actions/collect-training`, and all analytics
  endpoints. The failure mode is silent: no error is raised, no request is blocked,
  and only a `WARNING` log is emitted. If the Render deployment ever loses the env
  var (secret rotation error, environment rebuild), the entire API is exposed.
- **Recommendation**: Fail hard on startup if `API_SECRET` is empty:
  ```python
  if not API_SECRET:
      raise RuntimeError("API_SECRET env var must be set — refusing to start without auth")
  ```
  At minimum, return HTTP 503 instead of silently accepting requests.

### [COMPLIANCE] Done-flags set unconditionally after bare try/except in watch loop

- **Severity**: critical
- **File**: `src/scheduler/watch.py:1323–1358`
- **Evidence**: Two tasks set their done-flags unconditionally, violating the CLAUDE.md
  rule: *"done-flags must be conditional: `if self._safe_run(...): self._done = True`.
  Never set a done-flag unconditionally after `_safe_run`."*

  **Daily validation** (`watch.py:1344`):
  ```python
  except Exception as e:
      logger.warning("[WATCH] Validation failed: %s", e)
  self._daily_validation_done = True   # ← always set, even on exception
  ```
  **Daily build score** (`watch.py:1358`):
  ```python
  except Exception as e:
      logger.warning("[WATCH] Build score persistence failed: %s", e)
  self._daily_build_score_done = True  # ← always set, even on exception
  ```
  Both tasks bypass `_safe_run()` entirely and set their done-flags after a bare
  try/except. If the task fails (import error, DB unavailable), the done-flag is set
  and the task will **not** retry until the next calendar day.
- **Recommendation**: Wrap both tasks with `_safe_run()` and move the done-flag into the
  conditional branch:
  ```python
  if self._safe_run("daily validation", lambda: ...):
      self._daily_validation_done = True
  ```

### [TRADING SAFETY] Risk governor can be fully disabled via YAML config

- **Severity**: medium
- **File**: `src/risk/governor.py:355–362`, `config/settings.example.yaml:362`
- **Evidence**:
  ```yaml
  risk_governor:
    enabled: false  # false = disable all risk checks (DANGEROUS — never do this in live).
  ```
  When `enabled` is `false`, `RiskGovernor.check_trade()` returns `approved: True` for
  every request with no checks applied. There is no code-level safeguard preventing this
  from being set in a live-trading config by accident.
- **Recommendation**: Add a startup assertion that rejects `enabled: false` when
  `live_trading.enabled: true`. Log a prominent warning if disabled in shadow mode too.

  version. Add `psutil` to a `requirements-dev.txt` smoke-test if it is not in the
  standard install path.
