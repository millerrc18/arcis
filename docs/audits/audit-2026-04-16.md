## Critical Findings

### [TEST COVERAGE / COMPLIANCE] `scipy` and `numpy` missing from `requirements.txt`
- **Severity**: critical
- **File**: `requirements.txt` (root), `src/evaluation/statistics.py:14-15`, `src/features/regime.py:27`, `src/gate_evaluator.py:19`, `src/simulation/monte_carlo.py:9`
- **Evidence**:
  - `src/evaluation/statistics.py` does `import numpy as np` and `from scipy import stats` at the module top-level — these are hard imports, not guarded.
  - `src/features/regime.py` does `import numpy as np` at line 27.
  - `requirements.txt` lists only `scikit-learn>=1.4` (which pulls numpy transitively) but **does not list `scipy`** anywhere in any requirements file (`requirements.txt`, `requirements-cloud.txt`, `requirements-training.txt`).
  - `numpy` is also absent as an explicit pin; relying on scikit-learn's transitive dep is fragile — a future scikit-learn version could drop or replace it.
  - In a clean cloud deployment (`requirements-cloud.txt`), both `scipy` and `numpy` are completely absent. The Render API pod would crash importing `src.evaluation.statistics` or `src.features.regime`.
  - Confirmed by test collection errors in this audit run: `ModuleNotFoundError: No module named 'scipy'` blocked `test_statistics.py` from collecting.
- **Recommendation**:
  1. Add `scipy>=1.12,<2.0` and `numpy>=1.26,<3.0` to `requirements.txt`.
  2. Audit `requirements-cloud.txt` — if `statistics.py` or `regime.py` are reachable from the Render API, add them there too.

## High Findings

### [ARCHITECTURE] Circular imports: `risk.governor ↔ shadow_trading.executor` and `features.regime ↔ features.engine`
- **Severity**: high
- **Files**:
  - `src/risk/governor.py:638` (`from src.shadow_trading.executor import _get_current_price_safe` — deferred inside a function)
  - `src/shadow_trading/executor.py:370`, `:496`, `:518`, `:1695` (`from src.risk.governor import RiskGovernor, ...` — deferred inside functions)
  - `src/features/regime.py:30` (`from src.features.engine import _slope_direction` — top-level import)
  - `src/features/engine.py:237` (`from src.features.regime import compute_market_regime` — deferred inside a function)
  - `src/log_config.py:81` (`from src.observability.loki_handler import setup_loki_handler` — deferred) ↔ `src/observability/loki_handler.py:162` (`from src.log_config import StructuredFormatter` — top-level)
- **Evidence**: AST-based cycle detection found three bidirectional import chains. The `executor ↔ governor` and `regime ↔ engine` cycles are mitigated by using deferred (function-level) imports, but this is fragile: any refactor that lifts the deferred import to module scope will cause an `ImportError` at startup. The `log_config ↔ loki_handler` cycle is particularly risky because both are loaded early in the startup path.
- **Note**: Issue #434 tracks a related `startup.py ↔ startup_checks.py` circular import but does not cover these three pairs.
- **Recommendation**: Break cycles by extracting shared primitives into standalone utility modules (e.g., `src/risk/price_utils.py` for `_get_current_price_safe`, `src/features/regime_utils.py` for `_slope_direction`). Do not rely on deferred imports as a permanent solution.

### [TRADING SAFETY] `risk_governor.enabled: false` in config bypasses all 8 risk checks with no audit trail (pre-existing #438 adjacent)
- **Severity**: high
- **File**: `src/risk/governor.py:366`, `:394-400`
- **Evidence**:
  ```python
  self.enabled = risk_cfg.get("enabled", True)  # line 366
  ...
  if not self.enabled:  # line 394
      return {"approved": True, ...}  # all 8 checks skipped
  ```
  The config flag `risk_governor.enabled: false` causes `check_trade()` to return `approved: True` immediately with no position sizing, no sector cap, no VIX circuit breaker, no kill switch. The unauthenticated local `PUT /config` endpoint (`src/api/routes/system.py:361`) can set this flag without authentication (local-only but no session/CSRF protection). No log entry is emitted when the governor is disabled.
- **Recommendation**:
  1. Log a `WARNING` or `CRITICAL` level message when `enabled=False` is detected at startup and on every bypassed trade.
  2. Consider requiring `FORCE_DISABLE_GOVERNOR=true` environment variable in addition to the config flag (defense in depth).
  3. Add a `test_governor_disabled_logs_warning` test.

## Warnings

### [CODE QUALITY] 47 test functions with no `assert` statements
- **Severity**: medium
- **Files**: `tests/test_executor_import.py`, `tests/test_expanded_notifications.py`, `tests/test_validation.py`, `tests/test_dpo_pipeline.py`, others
- **Evidence**: AST scan found 47 `test_*` functions containing zero `assert` statements and no unittest assert method calls. Examples:
  - `test_executor_import.py::test_module_imports` — only does `import src.shadow_trading.executor` with no assertion.
  - `test_validation.py::test_db` — no assertions.
  - `test_dpo_pipeline.py::test_db` — no assertions.
  - Note: some of these use `pytest.raises()` which IS an assertion mechanism — those are false positives in the scan and are acceptable. The pure import-only and empty-body tests are the real gap.
- **Recommendation**: Audit the ~15 truly assertion-free tests and either add minimal assertions (e.g., `assert result is not None`) or convert them to `@pytest.mark.smoke` with a documented rationale.

### [CODE QUALITY] `open_shadow_trade()` and `open_live_trade()` are 555-line and 382-line god functions
- **Severity**: medium
- **Files**: `src/shadow_trading/executor.py:335` and `:1645`
- **Evidence**: Both functions contain inline risk checks, order submission, DB writes, broker fallback logic, Telegram notification, and position sizing — they share structural duplication but diverge enough to make a direct merge risky. The `run()` method in `src/scheduler/watch.py:1036` is 722 lines. All are grandfathered in `known_violations.json` but represent ongoing tech-debt.
- **Recommendation**: Per existing issue #367 and #418 — extract shared sub-flows (validation, DB write, notification) into private helpers. Tracked; no new issue filed.

### [ARCHITECTURE] FastAPI `@app.on_event("startup")` is deprecated
- **Severity**: low
- **File**: `src/api/app.py:43`
- **Evidence**: FastAPI emits `DeprecationWarning: on_event is deprecated, use lifespan event handlers instead` on every test run (275 warnings recorded). This will eventually be removed in a future FastAPI version.
- **Recommendation**: Migrate to the `lifespan` context manager pattern:
  ```python
  from contextlib import asynccontextmanager
  @asynccontextmanager
  async def lifespan(app: FastAPI):
      initialize_database()
      setup_logging()
      yield
  app = FastAPI(lifespan=lifespan)
  ```

### [SECURITY] Local API `PUT /config` modifies `settings.local.yaml` with no authentication
- **Severity**: low (by design — API binds to 127.0.0.1 only)
- **File**: `src/api/routes/system.py:361-384`
- **Evidence**: The `PUT /config` endpoint writes arbitrary YAML sections to `settings.local.yaml` including `risk_governor`, `shadow_trading`, and `live_trading` config. It requires no auth token. Any process on localhost (including a compromised subprocess or script) can disable the risk governor or enable live trading without a password.
- **Note**: CLAUDE.md documents that the local API binds to `127.0.0.1` only (confirmed in security test #348). This is a known design trade-off.
- **Recommendation**: Add a `X-Dashboard-Token` header check using a value from `.env`, or at minimum log all `PUT /config` calls with the full diff at `WARNING` level.

### [TEST COVERAGE] `src/strategy/` module has zero test coverage
- **Severity**: low
- **File**: `src/strategy/canary.py` (header: "Tests: none")
- **Evidence**: The `canary.py` module contains `canary_score()` — a pure function that scores trades 1-10 using 6 rules. It is called from `src/llm/packet_writer.py` and is part of the critical scoring pipeline. No test file covers it.
- **Recommendation**: Add `tests/test_canary.py` with boundary tests for each scoring rule (e.g., `strong_uptrend` +1, RSI > 75 -1). Pure function — trivial to test.
