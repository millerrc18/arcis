## Critical Findings

### [TEST COVERAGE] Missing `beautifulsoup4` dependency in requirements.txt
- **Severity**: critical
- **File**: `src/data_collection/fed_collector.py:33`
- **Evidence**: `fed_collector.py` does `from bs4 import BeautifulSoup` but `beautifulsoup4` (the package that provides `bs4`) is absent from `requirements.txt`. The CI test `test_all_src_modules_importable` in `tests/test_repo_structure.py` **fails** with:
  ```
  src.data_collection.fed_collector: No module named 'bs4'
  ```
  The FED communications collector is part of the daily overnight data pipeline (macro data). This dependency gap means any clean environment deployment will silently break FED data collection.
- **Recommendation**: Add `beautifulsoup4>=4.12,<5.0` to `requirements.txt`. Verify `lxml` or `html.parser` is acceptable as the parser (currently uses `"html.parser"` so no additional dep needed).

## High Findings

### [CODE QUALITY] `src/api/cloud_routes/trades.py` exceeds 400-line CI limit
- **Severity**: high
- **File**: `src/api/cloud_routes/trades.py` (427 lines, limit 400)

  This is not grandfathered — it is a new violation that will block CI.
- **Recommendation**: Extract the packet-building helpers or ledger routes (whichever was most recently added) into a separate module such as `api/cloud_routes/packets.py` or `api/cloud_routes/ledger.py` to bring the file under 400 lines.

### [CODE QUALITY] `src/startup_checks.py:_check_render_postgres` exceeds 60-line function limit
- **Severity**: high
- **File**: `src/startup_checks.py:271` (`_check_render_postgres`, 65 lines, limit 60)
- **Evidence**: `test_no_function_over_60_lines` in `tests/test_repo_structure.py` **fails** with:
  ```
  NEW VIOLATION: src/startup_checks.py:_check_render_postgres is 65 lines (max 60)
  ```
  Not grandfathered.
- **Recommendation**: Extract the Postgres table-count sub-check (roughly lines 305–335) into a private helper `_check_pg_table_counts(conn, config) -> list[CheckResult]` and call it from `_check_render_postgres`.

### [ARCHITECTURE] Circular import between `startup.py` and `startup_checks.py`
- **Severity**: high
- **File**: `src/startup.py:96`, `src/startup_checks.py:20`
- **Evidence**:
  - `startup.py:96`: `from src.startup_checks import (...)` — imports check functions
  - `startup_checks.py:20`: `from src.startup import CheckResult` — imports the dataclass back
  - This creates a direct circular dependency. Python resolves it via late binding (`# noqa: E402`) but this is fragile: any import-time side effect in either module (logging setup, DB init) can cause subtle failures or partial-init bugs.
- **Recommendation**: Move `CheckResult` (and any other shared types) to a thin `src/startup_types.py` module with no circular dependencies. Both `startup.py` and `startup_checks.py` import from it.

### [TEST COVERAGE] `psutil` import fails in CI environment despite being in requirements.txt
- **Severity**: high
- **File**: `src/monitoring/system_metrics.py:15`
- **Evidence**: `test_all_src_modules_importable` reports:
  ```
  src.monitoring.system_metrics: No module named 'psutil'
  ```
  `psutil>=5.9,<8.0` appears in `requirements.txt` but was not installed in the clean CI image used for this audit. The CI test treats this as a hard failure.
- **Recommendation**: Investigate whether `psutil` build fails silently on the target Python/OS combo (Python 3.11 on this host). Consider pinning to a specific build wheel or adding a `psutil` install health-check to the session-start hook.

## Warnings (Medium)

### [DOCUMENTATION] Stale table-count references across key files
- **Severity**: medium
- **Files**: `src/schema/registry.py:29`, `CLAUDE.md:14`, `MASTER.md:90,713`
- **Evidence**: Actual table count is **53** but docs are inconsistent:
  - `registry.py` docstring: "Owns tables: all **46** tables"
  - `CLAUDE.md`: "all **51** tables are defined in `src/schema/registry.py`"
  - `MASTER.md:90`: "53 tables" (correct) but line 713: "**51** tables"
  - `MASTER.md:832`: "**51** tables"
- **Recommendation**: Update `registry.py` docstring line 29 to `all 53 tables`. Update `CLAUDE.md:14`. Update `MASTER.md:713` and `MASTER.md:832` to 53.

### [CODE QUALITY] Silent `except Exception: pass` in `reconcile.py` outer scope
- **Severity**: medium
- **File**: `src/shadow_trading/reconcile.py:370`
- **Evidence**:
  ```python
  except Exception:
      pass
  ```
  This outer `try/except` wraps the entire IB position fetch block. A failure here is silently swallowed — the reconciler proceeds without any log warning that IB state was not checked. The inner exception (line 367) correctly logs a warning, but if that code path is never reached, the outer bare `pass` masks it.
- **Recommendation**: Change to `except Exception as e: logger.warning("[RECONCILE-PAPER] Outer IB block failed: %s", e)` so failures are visible.

### [TEST COVERAGE] 38 test functions without explicit `assert` statements
- **Severity**: medium
- **Files**: Various in `tests/`
- **Evidence**: Static analysis found 38 `def test_*` functions with no `ast.Assert` nodes. While several use `pytest.raises` (correctly), others are pure smoke tests (import-only) that provide coverage opacity:
  - `tests/test_executor_import.py:10: test_module_imports` — no assertions
  - `tests/test_recap_service.py:4: test_module_imports` — no assertions
  - `tests/test_cloud_analytics.py:4: test_module_imports` — no assertions
  - `tests/test_watch_import.py:4: test_module_imports` — no assertions
- **Recommendation**: Smoke tests are acceptable but should include at least `assert True, "smoke"` so CI can distinguish them from accidentally empty tests. Better: add one attribute check per import test.

### [SECURITY] FastAPI `@app.on_event` deprecation warnings on all routes
- **Severity**: medium
- **Files**: `src/api/cloud_app.py` (and related)
- **Evidence**: All test runs emit:
  ```
  DeprecationWarning: on_event is deprecated, use lifespan event handlers instead.
  ```
  FastAPI has deprecated `@app.on_event("startup")` in favor of the `lifespan` context manager (FastAPI ≥ 0.93). The current `requirements.txt` allows `fastapi>=0.115,<1.0` which enforces the newer API. This will become an error in a future FastAPI release.
- **Recommendation**: Migrate `@app.on_event("startup")` and `@app.on_event("shutdown")` handlers to the `@asynccontextmanager` lifespan pattern per FastAPI docs.

### [TRADING SAFETY] `journal/store.py:366` uses `except Exception: pass` to skip exit metadata
- **Severity**: medium
- **File**: `src/journal/store.py:366`
- **Evidence**:
  ```python
  except Exception:
      pass  # Exit metadata is best-effort — never block trade close
  ```
  The comment explains the intent but this silently drops MFE/drawdown calculation errors. If entry_price parsing produces NaN or infinity (due to upstream data issues), the metadata will be silently skipped, corrupting training data quality.
- **Recommendation**: Change to `except Exception as e: logger.debug("[JOURNAL] Exit metadata skipped for %s: %s", trade_id, e)` — keeps the non-blocking behavior but surfaces data quality issues.
