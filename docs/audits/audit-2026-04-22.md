## New Findings

### [SECURITY] Unauthenticated POST endpoints in cloud-deployed platform routes

- **Severity**: high
- **Files**: `src/api/cloud_routes/platform.py:222`, `src/api/cloud_routes/platform.py:325`
- **Evidence**:
  ```python
  # cloud_app.py:285-288 — registered without verify_auth dependency
  app.include_router(_platform_module.router)   # auth-free
  app.include_router(_walkforward_module.router) # auth-free

  # platform.py:222 — no dependencies=[Depends(verify_auth)]
  @router.post("/api/platform/promotions")
  async def promote_strategy(req: PromoteReq) -> dict:
      ...  # executes DB write with no auth check

  # platform.py:325 — no dependencies=[Depends(verify_auth)]
  @router.post("/api/platform/demotions")
  async def demote_strategy(req: DemoteReq) -> dict:
      ...  # executes DB write with no auth check
  ```
  Confirmed: `verify_auth = None` is set at module level. Contrast with all other cloud routes (council, analytics, diagnostics, etc.) which correctly use `dependencies=[Depends(verify_auth)]`.
- **Scope**: `demote_strategy` requires only a `strategy_id` (UUID) and a `reason` string — no confirmation token. Any unauthenticated HTTP client that can reach the Render API can demote any strategy. CORS is restricted to `halcyonlab.onrender.com` (not wildcard), so browser-based cross-origin attacks are blocked, but direct curl/script calls are not.
- **Distinct from #576**: #576 covers `src/api/routes/actions.py` (local routes). This is `src/api/cloud_routes/platform.py` — the cloud-deployed API.
- **Recommendation**: Add `dependencies=[Depends(verify_auth)]` to the `@router.post("/api/platform/promotions")` and `@router.post("/api/platform/demotions")` decorators. A two-line fix.

### [COMPLIANCE] Collector silent error dict returns in trends_collector.py and research_synthesizer.py

- **Severity**: medium
- **Files**: `src/data_collection/trends_collector.py:68`, `src/data_collection/research_synthesizer.py:89,139,142`
- **Evidence**:
  ```python
  # trends_collector.py:68 — returns dict with 'error' key on ImportError
  return {"terms_collected": 0, "spikes_detected": 0, "error": f"pytrends import: {exc}"}

  # research_synthesizer.py:89
  return {"error": str(e)}

  # research_synthesizer.py:139
  return {"papers_reviewed": len(papers), "error": "anthropic not installed"}
  ```
- **CLAUDE.md Rule**: "Collectors must raise on missing config — use `CollectorConfigError` from `src/data_collection/errors.py`. Never return a success dict with an `error` field silently."
- **Context**: `trends_collector` catches `ImportError` (missing `pytrends` package) and returns silently. `research_synthesizer` catches both a missing anthropic package and a missing API key — the API-key case should raise `CollectorConfigError`, not return a partial dict. The ImportError case for missing optional packages (pytrends, anthropic) may be intentionally lenient, but the `error` field return violates the rule regardless.
- **Recommendation**: Replace silent returns with `CollectorConfigError` raises for config/API-key problems. For optional dependencies (pytrends), log at WARNING and return the no-data result without the `error` key, or raise if the package was expected.
